# Negative proof (wasix-openblas)

## 0.3.28-1: a new build input (homescoop A6, 2026-10-18)

There's no earlier wasix-openblas. These are the cases the spec and build.sh refuse, run locally on macOS (wasixcc 0.4.7, wasix-sysroot -38, slicc-kernel 1.124.2 Node entry).

- **The bare-metal libc stubs** (the first local build, before wasm-abi.py dropped them on `__wasi__`): `-DOS_EMBEDDED` makes OpenBLAS's `driver/others/memory.c` define `puts`, `printf`, `getenv` and `atoi` stubs. obprobe's link failed with `wasm-ld: error: duplicate symbol: puts` (and `printf`, `getenv`), defined in `libc.a(puts.o)` and `libopenblas.a(memory.o)`. In a side module that doesn't link libc (numpy's), those stubs instead *replace* libc's, so `printf` and `getenv` silently do nothing there. build.sh now fails if the archive defines any of them.
- **A strong `xerbla_` / `xerbla_array_`:** OpenBLAS makes `xerbla_` a weak alias only on ELF, and the second local build had both strong (`T xerbla_`, `T xerbla_array_`). Linked `--whole-archive` beside numpy's `python_xerbla` or scipy's `xerbla_array_` (wasix_stubs.c), that's a duplicate symbol. build.sh now fails unless both are `W`. obprobe defines its own `xerbla_`, and an illegal `dgemm_` TRANSA reaches it (`xerbla_ DGEMM  1`).
- **An empty `lib/libopenblas.a`:** obprobe doesn't link (undefined `dgemm_`, `cblas_dgemm`, `dgesv_`, …), so cert/probe.mjs can't pass on an archive without BLAS and LAPACK.

## 0.3.34-1: the Renovate bump (#1173, 2026-10-19)

- **0.3.32's ARCH_WASM split:** the 0.3.28 wasm-abi.py looked for common.h's `#ifdef __EMSCRIPTEN__` empty `YIELDING`, which 0.3.32 moved into an `ARCH_WASM` block, and stopped with `YIELDING emscripten block not found` (host-build on #1173). Without the empty `YIELDING`, wasi takes ARCH_RISCV64's `nop` asm, which wasm can't assemble. wasm-abi.py now defines it ahead of the RISCV64 block and still fails when neither layout is there.
- **0.3.34's xerbla_ handler:** `driver/others/xerbla.c` now dispatches to an `openblas_set_xerbla` handler with a name length, so the old weak-`xerbla_` edit had no match (`no '#else…' to make weak`). wasm-abi.py now makes 0.3.34's `#else` `xerbla_` two-argument and weak (length = strlen); the probe's `xerbla_ DGEMM  1` and build.sh's `W xerbla_` check pass locally (macOS, wasixcc 0.4.7, wasix-sysroot -38, slicc-kernel 1.124.2).
- **0.3.34's own lapack/laed3 (cert-review fail on 28c185a0):** `lapack/laed3/laed3_{single,parallel}.c` replace netlib's `?laed3_` and declare `LAED4`/`LACPY`/`LASET` `void`, while the f2c'd netlib objects in the same archive define `?laed4_`/`?lacpy_`/`?laset_` returning `int`. A plain `-lopenblas` link of a `dsyevd_` caller warns and traps `unreachable` (n > 25), and py-numpy's `--whole-archive --fatal-warnings` link fails. Locally: obprobe (now with `dsyevd_` jobz=V, n=64) **doesn't link** against that tarball (`wasm-ld: error: function signature mismatch: dlacpy_`, `dlaset_`, …), and a `--whole-archive` link shows the six mismatches (`d/s` × `laed4_ lacpy_ laset_`). wasm-abi.py now turns file-scope `void UPPER(...);` prototypes in `lapack/**/*.c` into `int` (2 files), build.sh fails unless the whole archive links `--whole-archive --fatal-warnings`, and the rebuilt tarball passes the probe (eigenvalues and `A v - w v` within 1e-12).
- **The version line:** cert/probe.mjs now takes the expected `openblas_get_config()` version from package.json's `homescoop.upstream`, so an archive built from another OpenBLAS than the package says fails it.
